# 中国主要房地产房源平台「官方数据接入」合规调研报告

> 调研方式：全部结论基于 `web_search` + `web_fetch` 实测抓取，非记忆。
> 调研日期：2026-10（以抓取时的页面内容为准）
> **证据分级说明**：本报告对每条结论标注置信度——
> - **[已实测]** = 本人实际 fetch 到该 URL 并看到页面内容
> - **[官方原文]** = 平台官方域名/官方仓库自述
> - **[第三方旁证]** = 非官方站点（软件厂商文档、新闻）但内容一致且可信
> - **[未能验证]** = URL 存在但内容为 JS 渲染/被拦截，无法读取正文

---

## 0. 最重要的一个结论（先看这个）

**中国主流商业房源平台（贝壳、安居客、58、房天下、幸福里）没有任何一家向"第三方 SaaS 厂商"开放"批量获取二手房房源列表+详情+图片"的公开 API。**

它们**确实有官方开放平台**，但方向是反的：

| 平台开放平台的真实用途 | 说明 |
|---|---|
| **入向：帮经纪公司"发房"到平台** | 一键发房、同步房源、VR 推送 —— 数据从经纪公司流向平台 |
| **入向：帮经纪公司"管理部门账号"** | 门店/经纪人/端口/资金管理 |
| **出向：只给"认证经纪公司自己"看自己的数据** | 挂牌房源、带看、调价 —— 仅限本主体自有数据 |
| **出向：给银行/政府做"估值与验真"** | 壳e估、房本识别、押品监控 —— 不是房源列表 |

**唯一真正开放的"出向"批量数据通道是政府数据开放平台**（如深圳市政府数据开放平台），但它只给**按日汇总的成交量统计**，且服务条款**明令禁止转让数据资源**。

## 2. 逐平台详细说明

### 2.1 贝壳找房（Ke.com / 链家）

贝壳有**两个完全不同的官方平台**，必须分开看——这是本报告最容易被搞混的地方。

#### A. 贝壳开放平台 `open.ke.com` —— 面向金融/政务/企业的"估值与验真"服务

**[已实测]** 首页与产品导航实际抓取，产品线如下（原文菜单）：

- 房屋价值分析服务：`壳e估`、`房屋价值分析报告`、`房屋押品监控`、`成交案例库`
- 房产真实信息服务：`房本识别`、`房本验真`、`壳e勘-图片验真`、`壳e勘-数据验真`、`壳e勘-实地验真`
- 房产行业数据服务：**`RealData企业版`**、`房屋数据技术服务`、`房屋户型打分`、`房屋户型解读`、**`商房直连`**、`VR空间采集服务`
- 行业方案：**金融**、**政务**、数字科技

**能拿到的数据能力**（据金融行业页 [已实测] https://open.ke.com/industry/financial/ ）：
- 楼盘字典 **3亿+套**真房源数据，覆盖 **327个城市、75万个楼盘**（原文口径）
- 房屋价值批量评估（支持百万级批量分析）
- 成交案例库：相似房源推荐 3 套近期成交（覆盖 150+ 城市）
- 房产证 OCR 识别与验真、线下实勘

**客户案例（原文）**：中信银行（房抵贷风控）、千际投行（不良资产/法拍）、长虹佳华（押品验真）→ **说明真实客群是银行、AMC、持牌机构，不是普通 SaaS。**

**认证方式**：企业签约 + 控制台 `AppKey` / `AppSecret`。
- **[第三方旁证]** 集简云（iPaaS）对接教程实测记录了完整流程：登录 open.ke.com → `控制台—我的应用—创建应用` → 弹出 `Appkey` 和 `AppSecret`（仅首次创建时弹出）。
  来源：https://www.jijyun.cn/help/detail/1049

**联系入口 [已实测]**：`jiaoxiadan001@ke.com`（页面"咨询邮箱"），提供"1v1大客户服务、7×24小时响应、专属技术指导"。协议文件为《贝壳开放平台协议》。

**配额/费用**：**未找到公开信息**。页面未公布配额、价格、城市限制细则，一律走商务洽谈。

**⚠️ 关键结论**：`open.ke.com` **不提供"二手房列表检索"API**。它的产品是"给一套已知房子做估值/验真"，而不是"给我一批房子"。`商房直连` 与 `RealData企业版` 的具体接口能力页面为 404（实测 `/product/shangfangzhilian`、`/product/realdata` 均 404），**未找到公开信息**说明其开放边界。

#### B. 贝壳 AI 开放平台 `building.ke.com` —— 有 MCP，但许可受限

**[已实测]**
- `https://building.ke.com/` → 页面标题 **「贝壳 AI 开放平台」**
- `https://building.ke.com/mcp` → **GET 返回 HTTP 405 Method Not Allowed**（符合 Streamable-HTTP MCP 服务端只接受 POST 的特征，佐证该 MCP 端点真实存在）

**[官方原文]** 贝壳在 GitHub 以 `LianjiaTech/beike-ai-platform` 开源分发 CLI + AI Skills，README 明确写：

> 贝壳 AI 开放平台，为开发者提供房产信息查询、市场分析等 AI 能力。

Skill 清单（`skills/README.md` 原文表格）：

| Skill | 功能 |
|---|---|
| `beike-buy` | 二手房和新房购买助手：**房源搜索、小区详情、价格行情、经纪人咨询** |
| `beike-rent` | 租房助手：租房搜索、租金走势、看房预约 |
| `beike-market` | **市场行情和成交数据查询**：买卖行情、历史成交、租赁行情分析 |
| `beike-policy` | 购房政策顾问 |
| `beike-school` | 学区/学校查询 |
| `beike-sell` | 卖房业主助手：**查询名下挂牌房源、带看记录和调价动态** |
| `beike-decor` | 装修助手 |

**认证方式 [官方原文]**：`beike login` 打开登录页获取 API Key → `beike auth <KEY> --save`，密钥存于 `~/.beike/BEIKE_MCP_API_KEY`。
CLI 用法示例：`beike buy search -c 北京 -q "朝阳区 1000万以内 2居"`、`beike market search -c 北京 -q "朝阳区二手房"`。

**🚨 限制（这点最重要，直接决定能不能商用）**：
- `skills/README.md` 的「许可」一栏写：**「贝壳内部使用。」**
- `cli/README.md` 的「许可」一栏写：**「商业软件，仅限授权用户使用。」**
- 用户协议链接的 ID 为 **`beike_AI_open_Platform_private_protocol`**（*private protocol*，非公开协议）
  https://m.ke.com/user/commonProtocol?id=beike_AI_open_Platform_private_protocol

**结论**：`building.ke.com` 是**面向 AI Agent 的消费级/授权级通道**（个人账号取 Key、按对话查询），**不是**给 B2B SaaS 做批量数据抽取的通道。虽然技术上"自助取 Key"，但许可条款明确指向内部/授权用户，**未找到公开的企业配额与商用授权说明**。

**其他旁证**：贝壳商机平台曾公开分享 MCP 工程实践（InfoQ《贝壳商机平台：MCP 原理剖析及实践》 https://www.infoq.cn/article/dp5cpsbahkahaqmjhdsv ），正文为 JS 渲染，**[未能验证]** 具体工具列表与配额。

**明确结论**：第三方 SaaS **不能**通过贝壳合法获取"全量二手房列表+详情+图片"。
- 能谈的只有：`open.ke.com` 的**估值/验真/成交案例**（需企业签约）
- `building.ke.com` 的 AI 通道**需先解决许可问题**，且**未找到公开商用条款**

### 2.2 安居客（Anjuke）与 2.3 58同城房产 —— 同一套开放平台

安居客已被 58 同城收购，**两者共用同一个开放平台**。这是全报告中最"实在"的一个官方通道，但门槛是身份。

#### 官方入口（均已实测确认存在）

| 入口 | 用途 | 实测结果 |
|---|---|---|
| `https://qiye.anjuke.com/` | **网络门店**（B 端经纪公司工作台） | ✅ [已实测] 标题「网络门店」，功能含"在线录入/**系统对接导入房源**"、"端口资金管理"、"营销数据分析" |
| `https://hugopenapi.58.com/openapi` | **58房产开放平台**（开发者入口） | ✅ [已实测] 标题「58房产开放平台」 |
| `https://open.58.com/` | 58同城·开放平台（**全站级，非房产专用**） | ✅ [已实测] 标题「58同城·开放平台」，正文 JS 渲染 |
| `https://open.anjuke.com/` | — | ⚠️ 返回 HTTP 200 但**正文为空**，**未找到公开信息**证明其为准立开发者平台 |

#### 接入流程（**[第三方旁证]** 房软中介系统官方教程，含逐步截图）

来源：https://fangruan.com/help/detail/2549 （标题《对接三网（中国网络经纪人）(安居客)（58房产）》）

1. 登录网络门店 `https://qiye.anjuke.com/`，进入 **开放平台—授权管理**
2. **申请获取授权码**（原文注明"这一步需要管理员配合操作"）
3. 登录开放平台 `http://hugopenapi.58.com/openapi#/user/login` 注册（"仅需要一些基础的公司数据即可注册"）
4. 左侧【申请秘钥】，输入信息后得到**对接账号和密码**
5. 需手动开通三个接口：**一键发房、楼盘字典、三网经纪人/店查询及管理**
6. 【秘钥管理】→【管理秘钥】→ 复制 **`ClientID` 和 `ClientSecret`**
7. 填入第三方系统

#### 能力与限制

- **认证方式**：`ClientID` + `ClientSecret`（OAuth 风格的 client credentials），**但前置条件是"网络门店"企业管理员发放"授权码"** → 本质是**企业签约 + 主体授权双层**
- **数据能力**：只有 **`楼盘字典`**（小区/楼盘基础字典）+ **`一键发房`** + **`经纪人/店查询及管理`**
- **❌ 没有"二手房列表/详情/图片/成交"的检索接口**
- **门槛**：**必须是已开通网络门店的经纪公司**（即 58/安居客的付费 B 端客户）。第三方 SaaS 只能作为"经纪公司授权的工具"接入，**不能自己作为数据消费者接入**
- **费用**：**未找到公开信息**（端口套餐在 `qiye.anjuke.com` 内购买，非公开定价）
- 联系邮箱：`service@58.com`（页面底部 [已实测]）

#### 同生态旁证：多家房产 ERP 都做"同一个方向"

- 房软（深圳房软技术）：《对接三网》+《发布房源到安居客，58房产》 https://fangruan.com/help/detail/2550
- 房在线（厦门房在线科技）：《对接三网》 http://www.fangline.cn/tutorial/menuid7/submenuid421
- 众趣（3dnest）：《一键上安居客》《获取安居客token》 http://open.3dnest.cn/doc/open/one-click-upload/upload-anjuke/

**这些厂商做的全是"把经纪公司的房源推上平台"，没有一家在做"从平台拉取房源"。**

**明确结论**：第三方 SaaS **不能**以自己名义合法获取 58/安居客的房源数据。
- 能被授权的场景：你的客户**本身是 58/安居客的付费经纪公司**，你作为其**技术服务商**，通过它发放的授权码接入，且**只能操作它自己的房源**（发房/管理账号/读楼盘字典）
- 若客户不是认证经纪公司 → **无公开接入方式**

### 2.4 房天下（Fang.com / 搜房网）

**[官方原文]** 房天下官方新闻页实测（https://news.fang.com/2026-10-08/55146247.htm ）明确写出了开放平台地址与认证方式：

> 第二步，打开房天下开放平台（**ai.fang.com/open/**）登录你的账号，复制 **API Key** 发给专家……
> **API Key 用于连接你本人的房天下开放平台账号**

**关键事实**：
- **入口**：`https://ai.fang.com/open/`（官方新闻原文给出的 URL）
- **认证**：**API Key**，绑定"你本人的房天下开放平台账号"（账号级自助，无需企业签约）
- **页面底部导航 [已实测]** 含「开放平台」链接指向 `//open.fang.com`；`open.fang.com` 实测返 HTTP 200 但正文为空（SPA），存在 Web Archive 快照 `open.fang.com/#/home`（2025-12-10）
- **数据能力（官方宣传口径）**：真实在售、在租、成交数据；新房/二手房/租房/查房价；覆盖"主流城市"。房源来源三类：**经纪人挂牌、企业库、业主直挂**
- **定位**：接入 **WorkBuddy 开放平台** 与 **阿里千问开放平台**，以"官方 AI 专家/智能体"形态提供服务

**[未能验证]** `https://ai.fang.com/open/` 本人多次 fetch 均网络失败，**未能读取其开发者协议正文**，因此：
- **配额：未找到公开信息**
- **是否允许批量导出/转售：未找到公开信息**
- **费用：官方 FAQ 原文仅称「具体以平台说明为准」**

**明确结论**：房天下**有**面向开发者的 API Key 通道，但**公开材料把它定义为"AI 智能体接入"**，而非数据批量分发。第三方 SaaS 把 API Key 用于**对话式查询**是官方明示的场景；用于**批量抓取房源入库并对外提供**，**未找到任何授权依据** → 属于**高风险未授权用途**。

⚠️ 另需注意：`esf.fang.com/chengjiao/` 等是**公开网页**，可人工浏览，但**不等于**可程序化抓取（见第 3 节判例）。

## 3. 「爬虫 / 逆向 / 第三方 scraper」方案为何不可用

> 本节是本报告的**核心风险章节**。搜索"贝壳 开放平台""安居客 API"时，**返回结果中占比最高的是爬虫服务与逆向教程**。这些**全部不是官方渠道**。

### 3.1 先分类：网上这些"API"到底是什么

| 类型 | 典型形态 | 实际性质 | 判定 |
|---|---|---|---|
| **A. 第三方 scraper 平台** | Apify 上的 `Beike & Lianjia Property Scraper`、`Fang.com Real Estate Scraper`（含 `/api/mcp` 端点） | 第三方公司写的爬虫，**包装成"API/MCP"卖** | ❌ **违规**，与官方无关 |
| **B. 逆向教程** | 阿里云开发者社区 / CSDN 的《安居客 `item_get` - 获取详情数据接口对接全攻略》《58同城 `item_search` 获取搜索数据接口对接全攻略》《房天下 `item_get` 获取详情接口对对接全攻略》 | **逆向/中间人**得到的私有接口，教程指向某个第三方数据代理商 | ❌ **违规**，且接口随时失效 |
| **C. API 聚合市场** | 幂简集成 `apihub.explinks.com` 挂售"58房产营销服务API""58同城开放服务API" | **二道贩子**，非官方授权渠道 | ⚠️ **不可信**，需官方书面确认 |
| **D. 数据集镜像站** | `selectdataset.com` 收录"上海二手房网签数据""一手商品房成交（按日统计）信息" | 抓取政府开放平台再转售 | ❌ **违反政府平台服务条款**（见 2.6A） |
| **E. 官方渠道** | 本报告第 2 节列出的 `open.ke.com`、`hugopenapi.58.com`、`ai.fang.com/open/`、`open.xflapp.com`、`opendata.sz.gov.cn` | ✅ 官方 | ✅ 可用（附条件） |

**识别口诀**：凡是**不需要平台方授权码/企业签约、不需要你的客户是认证经纪公司、只要付钱就给你"item_get/item_search"** 的，**一定是爬虫或二道贩子**。官方渠道的特点恰恰相反——**它要求你的身份**。

### 3.2 法律风险：已有生效判例，赔偿 550 万元

这是本报告**最硬的一条证据**，且判决已生效。

**案由**：北京链家房地产经纪有限公司、天津小屋信息科技有限公司 诉 北京神鹰城讯科技股份有限公司、成都神鹰城讯科技有限公司（"**推推99**"产品）
**审理法院**：北京市海淀区人民法院（一审）
**结果**：判令消除影响，**连带赔偿经济损失 500 万元 + 合理开支 50 万元 = 550 万元**；一审判后被告上诉、**后撤回上诉，本案已生效**
**来源**：中国法院网，经辽宁省盖州市人民法院网站转载
https://ykgz.lncourt.gov.cn/article/detail/2023/01/id/7113312.shtml

**判决认定的侵权事实（原文要点）**：
- 被告通过"推推99"产品，**利用技术手段抓取、存储贝壳找房网中的房源基本信息、交易信息、特色信息、实勘图、VR图（全景图）、户型图**
- 抓取过程中**自动去除贝壳网房源图片水印**
- 将数据**通过信息网络向其用户或公众传播**（在推推99产品内展示、供用户编辑下载、发布至推推99房产网及第三方房产信息平台和微信）
- 使用计算机程序**伪装成真实用户访问贝壳网百万次**
- **认定依据**：《反不正当竞争法》第二条，构成不正当竞争
- 诉讼中法院作出**行为保全裁定**：立即停止抓取、存储；立即停止传播；**禁止以任何形式向其他任何主体提供涉案数据**

**法官说法的核心裁判规则（原文，直接决定 SaaS 能不能做）**：

> 涉案数据虽是二原告**向公众无差别的予以提供和展示的公开数据**，但这**并不意味着其他经营者可以不受任何限制的获取和使用**；认定获取和使用公开数据的行为是否构成不正当竞争，应结合获取、使用数据的**具体手段和方式**，综合考虑该行为**是否违反了相关行业的商业道德、对其他经营者的合法权益、消费者利益以及市场竞争秩序**所产生的影响等方面，进行分析判断。

**为什么这条对 SaaS 尤其致命**：本案被告的商业模式（抓数据 → 存到自己服务器 → 给用户展示/编辑/下载/转发）**与"房源数据类 SaaS"几乎一一对应**。法院认定的加重情节里，**"向用户或公众传播""供用户编辑和下载""脱离原平台控制存储"** 全部是 SaaS 的标配功能。

**法院还特别指出**：被告行为"**实为房产经纪公司或经纪人发布'虚假房源'提供了重要工具和便利条件**"——即**下游客户用数据干什么，会成为你的责任**。

**其他可援引的规范与学理**：
- 《反不正当竞争法》第二条（一般条款）、第十二条（互联网专条）
- 《最高人民法院关于适用〈中华人民共和国反不正当竞争法〉若干问题的解释》关于商业道德、竞争关系的规定（本案已积极适用）
- 云亭律师事务所《公开数据能否不加限制的使用？》 http://www.yuntinglaw.com/news/270
- 《刑法》第 285 条第 2 款（非法获取计算机信息系统数据罪）、第 286 条（破坏计算机信息系统罪）—— 若绕过技术措施（如破解签名、绕过风控、**突破 fangdi.com.cn 那类 412 反爬**），风险性质从民事升级为**刑事**
- 《个人信息保护法》—— 房源数据含房东姓名/电话、经纪人信息，属个人信息，抓取即触发单独同意要求

### 3.3 稳定性与工程风险（商业上同样致命）

| 风险 | 具体后果 |
|---|---|
| **接口随时失效** | 逆向接口无契约、无 SLA、无版本管理。平台一次前端改版/加签即全量失效 |
| **封号 / IP 封禁** | 触发风控导致账号封停；若使用客户（经纪公司）账号，**直接毁掉客户业务** |
| **数据质量不可控** | 法院已认定爬取数据助长"虚假房源"；脏数据进入你的 SaaS 会污染你的估值/推荐模型 |
| **无合规证明** | To B 采购流程必然要求**数据来源合法性承诺**。你无法出具任何授权文件 → **过不了甲方法务和尽调** |
| **融资 / 上市尽调失败** | 数据来源合规是尽调必查项；存在生效不利判例的商业模式会直接击穿估值 |
| **连带责任** | 若客户用你的数据发布虚假房源，你可能被认定为"提供工具和便利条件"（本案已如此认定） |

### 3.4 一句话总结

**"公开可见" ≠ "可自由抓取" ≠ "可商业转售"。**
中国法院已用一份**生效的 550 万元判决**明确否定了"抓取—存储—传播房源数据"的商业模式。**任何以爬虫为数据底座的房源 SaaS，在中国不具备可持续的合规基础。**

## 5. 给 B2B SaaS 产品的合规建议

### 5.1 先做「数据来源分层」，别把鸡蛋放在一个篮子

建议把数据需求拆成三层，**每层用不同的合法来源**：

| 层级 | 需求 | 合法来源 | 可行性 |
|---|---|---|---|
| **L1 市场行情** | 城市/区域成交量、价格指数、趋势 | **政府数据开放平台**（深圳 `opendata.sz.gov.cn` 已有 API）+ 官方指数产品 | ✅ 最高，但**不能转售原始数据** |
| **L2 小区/楼盘字典** | 小区名称、区位、建成年代 | 贝壳 `open.ke.com`（企业合作）、58/安居客 `楼盘字典`（需经纪公司身份） | ⚠️ 需商务/身份 |
| **L3 房源明细** | 在售房源列表、详情、图片、成交 | **无公开合法通道** | ❌ 不要做 |

**结论：把产品定位在 L1+L2，不要试图用 L3 做护城河。**

### 5.2 可落地的合法路径（按推荐度排序）

1. **走政府数据开放平台（首选起步）**
   - 注册**机构账号**（`opendata.sz.gov.cn` 支持机构注册），创建应用、订阅接口
   - **必须做**：① 成果中标注"数据来源：深圳市政府数据开放平台"；② **绝不把原始数据资源转售/转分发**；③ 只输出你加工后的**派生指标**（如自建指数、评分），并明确标注为你的分析成果（服务条款第四项(一)6 要求"清楚地表明所做的任何数据分析或应用是个人或公司的行为"）
   - 注意：条款保留收费权，建议留存商务沟通记录
   - 建议**多地复制**：深圳、杭州已跑通；上海、广州、北京待补

2. **走官方商务合作（针对 L2）**
   - 贝壳：`open.ke.com` 咨询邮箱 `jiaoxiadan001@ke.com`，走"1v1 大客户"谈**估值/验真/成交案例**合作
   - 房天下：`ai.fang.com/open/` 取 API Key 做**智能体对话式**场景（官方明示场景），**不要**用于批量入库
   - **签约时必须书面确认四件事**：① 是否允许缓存/落库；② 是否允许向你的 SaaS 客户展示；③ 配额（QPS/日调用量）；④ 是否允许用于模型训练

3. **走「客户授权」模式（唯一能碰 L3 的合法姿势）**
   - 即 58/安居客/幸福里的真实模式：**你的客户是认证经纪公司**，由**客户管理员**在 `qiye.anjuke.com` 发放**授权码**，你凭 `ClientID`/`ClientSecret` 接入
   - **边界必须写死**：只能访问**该客户自己的**房源与账号数据；**不得跨客户聚合**；**不得留存超出服务期**
   - 合同里加入：客户保证其为合法授权主体、数据权属归客户、你仅为受托处理方（可对应《个人信息保护法》的**受托处理**定位）

4. **自建/采购替代数据（长期）**
   - 与**持有牌照的评估机构**（本案贝壳的客户类型：中信银行、千际投行）合作
   - 采购**持牌数据服务商**的合规数据产品
   - 与经纪公司**直接签订数据合作协议**（绕开平台，从数据源头拿授权）—— 这是最干净但最慢的路

### 5.3 绝对不要做的事（红线清单）

- ❌ 采购 Apify / CSDN"item_get 接口"类 scraper 或逆向接口作为生产数据源
- ❌ 抓取贝壳/安居客/58/房天下/幸福里页面（含公开页面）并落库
- ❌ 去除、替换或遮挡原平台水印/标识（**本案明确的加重情节**）
- ❌ 伪装 User-Agent、破解签名、绕过风控（如突破 fangdi 的 412）→ **刑事风险**
- ❌ 把政府开放平台数据转分发给 SaaS 客户（**直接违反服务条款**）
- ❌ 抓取含房东姓名/电话的字段（**个人信息保护法**）
- ❌ 在 BD/融资材料中声称"已对接贝壳/安居客官方 API"——除本报告 2.1–2.5 所列条件外，**该表述不实**

### 5.4 内控建议

1. **建立数据来源台账**：每个数据字段标注来源、授权依据（合同编号/条款截图）、有效期
2. **出具《数据来源合法性说明》**：To B 投标必备，能出示官方授权文件 vs 不能，是分水岭
3. **在合同中对客户做用途限制**：禁止客户用你的数据发布虚假房源（切断 3.2 判例中的"提供工具"责任链）
4. **建立下架响应机制**：政府平台要求数据下线时能快速停止使用（条款义务）
5. **定期复核**：官方开放平台政策变动频繁（如房天下/贝壳 2026 年新增 AI 开放平台），建议每季度复核一次
